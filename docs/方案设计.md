## 三、下载策略

### 3.1 多平台支持策略

```
视频 URL 输入
    │
    ├── 是抖音链接？──→ douyin.py 专用解析（A-Bogus 签名）
    │   ├── 方案一：官方 API + A_Bogus
    │   ├── 方案二：tikwm.com 备用 API
    │   └── 方案三：cooluc API
    │
    └── 其他平台 ──→ yt-dlp 通用解析器
        ├── extract_info(download=False) → 获取元数据 + 格式列表
        └── download() → 下载视频
```

### 3.2 yt-dlp 配置策略

```python
# 国内站点配置（Bilibili、抖音、爱奇艺等）
ydl_opts_cn = {
    "proxy": "",                          # 绕过系统代理直连
    "nocheckcertificate": True,           # 忽略 SSL 证书检查
    "legacy_server_connect": True,        # 兼容旧版 TLS 服务器
    "extractor_retries": 5,               # 提取重试
    "retries": 10,                        # 下载重试
    "socket_timeout": 30,                 # 连接超时
}

# 境外站点配置（YouTube 等）
ydl_opts_intl = {
    # 允许系统代理
    "nocheckcertificate": True,
    "extractor_retries": 3,
    "retries": 5,
    "socket_timeout": 60,
}
```

### 3.3 视频合并策略

```
检测 ffmpeg 是否可用
    │
    ├── 有 ffmpeg → "bv*+ba/b" （最优视频流 + 最优音频流 → 合并）
    │   └── 优势：可以下载到更高清晰度（1080p+ YouTube）
    │
    └── 无 ffmpeg → "bestvideo/best" （单流直接下载）
        └── 降级：自动选择已包含音频的最佳视频流
```

### 3.4 清晰度去重逻辑

```python
seen = set()
unique_formats = []
for fmt in formats:
    # 构建唯一键：分辨率 + 编码 + 音频情况
    key = (fmt.get('resolution'), fmt.get('vcodec'),
           fmt.get('acodec') != 'none')
    if key not in seen:
        seen.add(key)
        unique_formats.append(fmt)
```

### 3.5 文件命名与存储

```
downloads/
├── {video_id}_{title_slug}.mp4       # 下载的视频
├── {video_id}_subtitle.vtt           # 字幕 VTT 格式
├── {video_id}_subtitle_zh.vtt        # 中文字幕
└── {video_id}_audio.wav              # Whisper 转录用临时音频
```

命名规则：

- 视频 ID + 标题 slug 化（去除特殊字符、截断长度）
- 自动处理重名（添加数字后缀）

## 四、字幕与 AI 处理流程

### 4.1 字幕提取三级策略

```
视频输入
    │
    ├── 优先级 1：官方字幕
    │   ├── B站 → 直接调用 B站 API 获取 JSON 字幕
    │   └── 其他 → yt-dlp 获取 subtitles 列表，下载解析
    │
    ├── 优先级 2：自动字幕
    │   └── yt-dlp 获取 automatic_captions（如 YouTube 自动生成）
    │
    └── 优先级 3：ASR 语音识别
        ├── 下载音频（分离音频流或提取音频）
        ├── faster-whisper 转录
        │   ├── 模型选择：tiny / base / small / medium / large
        │   ├── 语言：自动检测 或 手动指定
        │   └── 可选 prompt 提示词（减少同音字错误）
        └── 输出带时间戳的字幕片段
```

### 4.2 AI 总结 Prompt 设计

```markdown
你是一个专业的视频内容分析师。请根据提供的视频信息生成：

📌 **视频摘要**（2-3 句话概括视频主要内容）

🔑 **核心要点**（5-8 个要点，每个一行，使用数字序号）

输入信息：

- 视频标题：{title}
- UP 主：{uploader}
- 视频简介：{description}
- 字幕内容：{subtitles}
```

### 4.3 思维导图生成 Prompt

```markdown
请将以下视频内容提炼为结构化的思维导图（Markdown 多级列表格式）。
要求：

1. 使用 # ## ### 层级结构
2. 主题作为一级标题
3. 关键分支作为二级标题
4. 细节要点作为三级或更深层级
5. 保持逻辑清晰、层次分明

视频标题：{title}
内容文本：{text}
```

### 5.2 状态管理

采用 React 本地状态 + 自定义 Hook 模式，无需引入 Redux 等全局状态库：

| 状态     | 管理方式               | 作用域              |
| -------- | ---------------------- | ------------------- |
| 用户认证 | localStorage + Context | 全局                |
| 视频信息 | useState               | VideoInfo           |
| 下载进度 | SSE 流解析             | DownloadProgress    |
| 字幕数据 | useState               | VideoSubtitle       |
| 播放同步 | useVideoSync Hook      | VideoSubtitle Tab 1 |
| 下载历史 | localStorage           | DownloadHistory     |

### 5.3 前后端通信模式

```
┌─ 同步请求 ─────────────────────────────┐
│ POST /api/info                          │
│ fetch() → await res.json()              │
│ 适用：获取视频信息、用户认证等            │
└─────────────────────────────────────────┘

┌─ SSE 流式 ─────────────────────────────┐
│ POST /api/download                      │
│ POST /api/video/summarize-text          │
│ const reader = res.body.getReader()     │
│ while (!done) { parse SSE data: {...} } │
│ 适用：下载进度、AI 流式生成              │
└─────────────────────────────────────────┘

┌─ 代理请求 ─────────────────────────────┐
│ GET /api/thumbnail?url=...              │
│ GET /api/file/{filename}                │
│ 适用：绕过防盗链、文件下载               │
```

## 七、部署方案（规划）

### 7.1 开发环境

```bash
# 后端
cd backend
python -m uvicorn main:app --host 0.0.0.0 --port 8000 --reload

# 前端
cd frontend
npm run dev
```

### 7.2 生产环境

| 组件     | 方案                                   | 说明                           |
| -------- | -------------------------------------- | ------------------------------ |
| 前端部署 | Nginx 静态托管 / Vercel / Netlify      | 构建后为纯静态文件             |
| 后端部署 | Gunicorn + Uvicorn workers / Docker    | 多 worker 提升并发             |
| 反向代理 | Nginx                                  | 统一入口、SSL 终止、限流       |
| 文件存储 | 本地 → OSS/S3（扩展）                  | 初期本地存储，后期迁移云存储   |
| 数据库   | SQLite → PostgreSQL（扩展）            | 初期 SQLite 够用，后期按需升级 |
| 进程管理 | systemd / supervisord / Docker Compose | 保证服务自启和健康监控         |

### 7.3 Docker 化（推荐）

```dockerfile
# 后端 Dockerfile
FROM python:3.11-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install -r requirements.txt
COPY . .
CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]

# 前端 Dockerfile
FROM node:18-alpine as build
WORKDIR /app
COPY package*.json .
RUN npm ci
COPY . .
RUN npm run build

FROM nginx:alpine
COPY --from=build /app/dist /usr/share/nginx/html
COPY nginx.conf /etc/nginx/conf.d/default.conf
```
