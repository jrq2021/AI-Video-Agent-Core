# 独立解析页与首页分屏滚动设计

## 目标

将首页内的“解析工作台”迁移到独立的 `/parse` 页面；首页改为按视觉模块逐屏吸附滚动。解析页与个人中心保持普通连续滚动。

## 范围

- 迁移链接输入、视频信息、下载、字幕提取、AI 总结和思维导图到 `/parse`。
- 保持登录、会员额度、下载 SSE、解析历史和后端 API 的现有行为。
- 将首页及导航中的“开始解析”入口切换为访问 `/parse`。
- 让个人中心的“继续解析”进入 `/parse`，并恢复被选中的历史记录。
- 只改前端。后端接口及数据结构不变。

## 页面与路由

现有的轻量路由仍由 `frontend/src/App.jsx` 管理，不引入新依赖。

| 路径 | 页面 | 滚动行为 |
| --- | --- | --- |
| `/` | 首页：首屏、功能、套餐、FAQ、联系和页脚 | 分屏吸附 |
| `/parse` | 解析工作台：输入、解析结果、下载与 AI 分析 | 普通连续滚动 |
| `/profile` | 个人中心与解析历史 | 普通连续滚动 |

直接访问路径和浏览器前进/后退继续使用已有的 `history.pushState` / `popstate` 模式。

## 组件边界与数据流

新增 `ParsePage`，只负责组织解析工作台的视觉结构：

- 使用既有 `VideoInput`、`VideoInfo` 和 `VideoSubtitle`。
- 接收用户、额度、弹窗及解析回调作为 props，不直接复制认证或额度逻辑。
- 在解析完成后并排呈现下载信息和 AI 分析，保留现有窄屏单列布局。

`App` 继续持有跨页面状态：当前用户、额度、登录/升级弹窗、当前视频、当前解析历史和解析回调。这样从个人中心恢复历史时，`App` 先切换到 `/parse`，再调用原有解析逻辑并将历史产物传入 `VideoSubtitle`。

## 导航

`Navbar` 改为理解“首页”和“解析页”两种上下文：

- 在首页，首页内部项目仍平滑滚动至对应模块；“解析工作台”和所有 CTA 跳转 `/parse`。
- 在解析页，“首页”返回 `/`；“解析工作台”保持当前页；功能、套餐、FAQ、联系入口回到首页并定位对应模块。
- Hero 与功能展示区中原本指向 `#download-workspace` 的链接改为解析页跳转。

## 首页分屏滚动

首页使用一个专用滚动容器，而不是修改全局页面滚动：

- 容器在桌面端使用 `scroll-snap-type: y mandatory`，每个首页模块以 `scroll-snap-align: start` 对齐。
- Hero、功能展示和其他首页内容以自然高度渲染；长内容（尤其 FAQ）可在本屏内继续阅读，不用 JavaScript 锁定滚轮或强制跳页。
- 小屏和 `prefers-reduced-motion: reduce` 使用 `scroll-snap-type: y proximity` 或关闭强制吸附，避免触控与可访问性问题。
- `ScrollExperience` 的模块清单移除已迁出的 `download-workspace`，其余首页视觉效果继续跟随新的首页滚动容器。

## 非功能要求

- 不新增运行时依赖；使用原生 CSS scroll snap 和现有 React 状态。
- 所有现有 API 请求地址、额度校验、SSE 进度处理和 IndexedDB/服务端历史同步保持不变。
- 导航、键盘焦点和“减少动态效果”偏好不能被滚动效果阻断。

## 验收标准

1. 打开 `/` 时，看不到链接输入和视频结果区；首页模块可逐屏吸附滚动。
2. 点击任意“开始解析”或“解析工作台”入口，地址变为 `/parse`，并能输入链接解析。
3. 在 `/parse` 执行下载、字幕、总结、思维导图时，原有额度与历史记录逻辑正常工作。
4. 从个人中心选择继续解析后，页面转到 `/parse` 并恢复所选视频与已有产物。
5. `/profile` 与 `/parse` 不启用首页的分屏吸附效果。
6. 前端生产构建成功。
