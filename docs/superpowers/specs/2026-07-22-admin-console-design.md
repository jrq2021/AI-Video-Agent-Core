# 后台管理系统设计

## 目标

在现有站点内提供一个仅运营者可访问的 `/admin` 管理入口，用于查看核心运营数据、管理用户账号与会员权益、批量生成和管理兑换码。第一版保持单人运营的简单模型，不新增独立子域名、支付后台或复杂的角色系统。

## 范围

### 包含

- 管理员白名单访问控制。
- 概览仪表盘：总用户、今日新增、有效付费用户、今日兑换数、近 7 日注册趋势、套餐分布、卡券状态汇总。
- 用户列表：搜索、筛选、分页、套餐与使用额度展示。
- 用户操作：套餐调整、禁用/恢复、逻辑删除/恢复。
- 卡券：批量生成、复制、CSV 导出、状态筛选、撤销、兑换详情。
- 管理操作日志。

### 不包含

- 独立后台项目或新的子域名。
- 多角色、管理员邀请或后台内配置管理员。
- 订单退款、财务报表、支付通道配置。
- 物理删除用户、订单、兑换记录或解析历史。

## 访问控制与安全

生产环境增加 `ADMIN_EMAILS`，用英文逗号分隔管理员邮箱。服务端对每一个 `/api/admin/*` 接口验证现有 JWT，并检查当前用户邮箱是否存在于白名单；前端路由保护只改善体验，不能作为授权依据。

用户表增加账号状态：`active`、`disabled`、`deleted`。禁用或逻辑删除的用户不能获得登录态，也不能使用已存在的登录态调用受保护接口。恢复操作将状态改回 `active`。

管理员不能操作自己的账号状态，也不能删除、禁用或降级自己。所有会改变用户状态、套餐或卡券状态的接口必须记录操作日志，包含管理员 ID、动作、对象类型、对象 ID、变更前后摘要和时间。

## 页面与交互

### `/admin` 概览

桌面端使用侧栏导航，包含“概览、用户、卡券、操作记录”；移动端折叠为顶部菜单。

概览顶部展示四个指标：总用户、今日新增、有效付费用户、今日兑换数。下方展示近 7 日注册折线图、当前套餐分布环图，以及有效/已用/撤销/过期卡券数量。数据加载时显示骨架屏；无数据时展示空状态；接口失败时显示可重试提示。

### 用户

用户列表展示用户名、邮箱、注册时间、状态、当前套餐、到期时间和当日使用量。支持用户名/邮箱关键词搜索，按账号状态、套餐筛选并分页。

选择用户后在详情抽屉中查看会员状态及最近卡券兑换信息。管理员可：

- 调整为免费、Pro 周卡/月卡/年卡或 Ultra 终身；
- 禁用或恢复；
- 逻辑删除或恢复已删除账号。

每一项破坏性或权益变更操作先显示二次确认对话框，说明影响范围。逻辑删除保留订单、兑换记录和解析历史，恢复后用户继续使用原始账号。

### 卡券

卡券生成表单支持：套餐（Pro/Ultra）、有效类型（Pro 周/月/年，Ultra 固定终身）、数量（1–100）、有效期天数、备注、单张可兑换次数。生成成功后显示本批兑换码，支持复制单个、复制全部和导出 CSV。

卡券列表支持按有效、已用、已撤销和已过期筛选，展示套餐、类型、兑换进度、创建时间、到期时间、兑换人和兑换时间。仅允许撤销未使用或仍有剩余兑换次数的卡券；撤销后不能再兑换，既有兑换记录不受影响。

### 操作记录

按时间倒序展示管理员账号、动作、对象、结果摘要和操作时间；只读，不支持编辑或删除。第一版保留最近 90 天记录，超期记录由启动时的轻量清理逻辑移除。

## 数据与接口

继续使用现有 SQLite 文件：`users.db` 存用户和管理日志，`membership.db` 存会员与卡券。统计查询在服务端完成，前端只渲染返回的聚合数据。

新增的管理员 API 位于 `/api/admin/`：

- `GET /api/admin/overview`
- `GET /api/admin/users`
- `GET /api/admin/users/{user_id}`
- `PATCH /api/admin/users/{user_id}/membership`
- `PATCH /api/admin/users/{user_id}/status`
- `GET /api/admin/coupons`
- `POST /api/admin/coupons/batch`
- `POST /api/admin/coupons/{code}/revoke`
- `GET /api/admin/coupons/export`
- `GET /api/admin/audit-logs`

管理员卡券接口复用现有卡券生成、撤销、会员设置和兑换数据，不复制或改变现有普通用户兑换流程。

## 验证

后端测试覆盖：非管理员拒绝访问、禁用/删除用户无法认证、管理员不能操作自己、套餐与卡券变更写入日志、批量卡券生成及撤销边界、概览统计正确。

前端验证：未授权访问跳转首页；概览、列表、空状态和错误状态可显示；搜索/筛选/分页参数正确；批量生成后复制与导出使用服务端返回结果；破坏性操作必须经过确认。

构建完成后仍通过后端全量测试与前端生产构建。上线时保持现有 Nginx 配置，只替换本项目的后端进程和前端静态目录。
