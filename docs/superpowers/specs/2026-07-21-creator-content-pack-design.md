# 创作者内容包与兑换运营设计

## 目标

把当前的“视频下载 + 字幕 + 总结”工具升级为可通过闲鱼兑换码销售的创作者工作台。付费用户应当能从一个公开且有权处理的视频链接，得到可直接复用的内容资产，而不只是更高的下载次数。

首期交付四项互相配合的能力：

1. 独立的兑换中心与可见的套餐权益，减少闲鱼购买后的操作咨询。
2. Pro/Ultra 专属的批量解析队列，支持一次提交多个链接并持续查看结果。
3. 带时间轴的双语字幕，支持中英互译并导出 SRT/VTT。
4. AI 创作包：从字幕生成标题、口播提纲、平台文案和高光时间点，并导出 Markdown。

重点是让用户感知“下载后能立即发布、学习或归档”的结果。所有能力仅面向本人拥有或已获授权的公开内容；不承诺突破付费、私密或受保护内容的访问限制。

## 已有基础与约束

- 兑换码数据库、一次性兑换、套餐叠加和价格区兑换表单已经存在，首期复用而不另建支付系统。
- 会员的每日用量保存在 `user_membership.daily_usage_json`，适合新增额度键，不需要修改用户主表。
- `parse_history` 已保存字幕、分段、总结和导图，可扩展保存翻译与创作包，避免用户重复付费生成。
- `parse_video()` 会在缺字幕时触发音频下载和 ASR；批量任务不能无上限并发，也必须在任务失败时退还相应额度。
- 当前项目为单体 FastAPI + SQLite。首期采用持久化任务表与进程内单消费者，不引入 Celery、Redis 或新的云服务。

## 套餐与兑换策略

### 面向闲鱼的可售卡种

主推 Pro 兑换卡，支持 7 天、30 天和 365 天三种有效期。已有 Ultra 终身卡继续兼容已售兑换码，但不作为新用户的主推商品，避免对持续发生的转写与模型成本作无限承诺。

券码的有效期是“未兑换前可使用的截止时间”；套餐有效期从成功兑换时开始计算。重复兑换同一 Pro 套餐时顺延到期时间。

卖家在本地执行受控脚本生成、查看和作废券码；不在公网暴露无鉴权的券码管理接口。脚本至少支持：

- 生成指定数量的 Pro 周卡、月卡、年卡；可添加订单备注和券码过期日。
- 列出券码状态、已兑换账号 ID、兑换时间与套餐到期时间。
- 作废未兑换券码。

### 首期权益

| 权益 | 免费版 | Pro | Ultra（兼容） |
| --- | --- | --- | --- |
| 单条下载与基础字幕 | 保持现状 | 保持现状 | 保持现状 |
| 批量解析 | 不可用 | 每批最多 5 条 | 每批最多 15 条 |
| 每日批量解析条数 | 0 | 10 | 30 |
| 双语字幕 | 不可用 | 可用 | 可用 |
| AI 创作包 | 不可用 | 可用 | 可用 |
| 每日创作额度（翻译或创作包各扣 1） | 0 | 10 | 30 |
| 思维导图导出 | 不可用 | 可用 | 可用 |

所有数值放在 `PLAN_CONFIG`，而不是写死在组件中；后续可按实际模型成本调整。原有下载额度、总结额度和 Ultra 已售权益保持兼容。

## 用户流程

### 兑换中心

1. 用户从闲鱼收到券码后，注册并登录。
2. 在 `/redeem` 或价格区点击“兑换会员码”，输入券码。
3. 成功页明确展示套餐名称、到期日、今日批量解析剩余条数、今日创作额度和“立即去解析”按钮。
4. 个人中心同样展示这些权益与快捷入口；失败信息区分未登录、无效、已使用、过期和已是长期会员。

价格区现有的兑换输入保持可用，但应链接至独立兑换中心，避免用户在首页长页面中寻找输入框。

### 批量解析

1. Pro/Ultra 在 `/parse` 选择“批量解析”，粘贴多行链接。
2. 前端先去重、去空行、展示识别到的条数与套餐上限；超过上限不提交。
3. 后端创建批次和每个条目的持久化记录，按全局单并发、单用户单活跃批次依次处理。
4. 每个条目执行现有 `parse_video()`，完成后写入该用户的解析历史；用户可从任务列表打开对应解析页继续下载、生成字幕或创作内容。
5. 每个条目开始处理时扣 1 条批量解析额度；因平台不可访问、解析失败或服务异常而失败时自动退回该条额度，且同一条目最多退回一次。

批量解析只负责解析标题与字幕/ASR，不自动下载视频、不自动调用翻译或创作包。这样可以控制成本，也让用户明确决定哪些视频值得继续处理。

### 双语字幕与创作包

解析工作台在已有的“完整字幕”旁增加“创作包”页签。

- 完整字幕页：Pro/Ultra 可选择目标语言（首期仅简体中文与英语），生成后按原时间轴显示原文/译文，可导出双语 SRT/VTT。已有的纯原文导出继续免费保留。
- 创作包页：Pro/Ultra 点击生成后，得到一个固定结构：内容角度、一句话摘要、5 个标题、60 秒口播提纲、小红书笔记、公众号摘要和 3–5 个高光时间点。所有内容基于现有字幕；无有效字幕时不调用模型并指引先提取字幕。
- 每次成功开始翻译或创作包前扣 1 个每日创作额度。成功结果自动写入解析历史；同一解析记录、同一目标语言或同一创作包版本再次打开时读取缓存，不重复扣费。
- 模型返回失败、格式不完整或网络错误时不扣费；前端显示可重试的明确错误状态。

首期不做音视频自动剪辑、实际去水印、社媒账号发布、多人协作、文档 DOCX/PDF 生成或任意语言翻译。

## 路由与前端边界

沿用当前轻量级路由，不引入 React Router。

| 路径 | 页面责任 |
| --- | --- |
| `/parse` | 单条解析与批量解析入口、批量任务进度、单条内容资产 |
| `/redeem` | 券码兑换、已生效权益、上手步骤 |
| `/profile` | 套餐、到期日、全部今日额度、解析历史 |

新增组件保持职责单一：

- `RedeemPage`：只处理展示、输入、兑换结果和导航；兑换 API 调用由共享会员 hook 提供。
- `BatchParsePanel`：输入、链接预校验、提交和轮询；不重复单条解析逻辑。
- `BatchJobList`：展示批次及每个条目的排队、处理中、完成和失败状态。
- `CreatorPackPanel`：翻译、创作包、缓存结果与导出；通过 props 接收字幕、分段、用户和额度。
- `creatorPack` 服务：生成 Markdown 导出文本以及纯前端的 SRT/VTT 双语格式化，提供单元测试。

`VideoSubtitle` 继续作为内容资产区域的容器；如果新增内容使它过大，应提取翻译与创作包为独立子组件，而不是继续把状态塞进单文件。

## 后端数据与接口

### 会员与券码

- `QuotaInfo` 和套餐 API 新增 `daily_batch_items_limit/used`、`daily_creator_credits_limit/used`、`can_batch_parse`。
- `check_and_consume_quota` 新增 `batch_parse`、`translate`、`creator_pack` 动作。翻译和创作包映射到 `creator_credits`；批量解析映射到 `batch_items`。
- 新增幂等退款函数。它以批次条目 ID 为审计键，在同一事务中减少已用额度、写入带 `refund` 标记的 `usage_logs`，重复调用无副作用。
- `weekly` 成为 Pro 券码的合法 `order_type`，有效期为 7 天；既有 monthly/yearly/lifetime 行为不变。

### 批量任务

在 `batch_jobs.db` 中创建：

- `batch_jobs`：`id`、`user_id`、`status`、`total_count`、`completed_count`、`failed_count`、`created_at`、`updated_at`。
- `batch_job_items`：`id`、`job_id`、`position`、`url`、`status`、`title`、`record_key`、`error_message`、`quota_charged`、`quota_refunded`、时间戳。

接口：

- `POST /api/batch-jobs`：登录且有批量权益，接收 URL 数组，创建批次。
- `GET /api/batch-jobs`：返回当前用户最近批次摘要。
- `GET /api/batch-jobs/{job_id}`：返回条目列表与进度。

应用启动时将意外中断的 `running` 条目恢复为 `queued`。同一用户存在 `queued/running` 批次时拒绝新建批次；全局消费者一次只处理一个条目。任务结果只对所属用户可见。

### 内容资产

新增请求模型与接口：

- `POST /api/video/translate-subtitles`：接收 `segments`、`source_language`、`target_language` 和 `record_key`，返回带译文的原时间轴分段。
- `POST /api/video/creator-pack`：接收 `subtitles`、`segments`、`title` 和 `record_key`，返回结构化 JSON 创作包。

DeepSeek 调用应使用明确的 JSON 输出约束。后端校验数组长度、分段顺序、必填字段和最大文本长度；校验失败视作任务失败并不扣费。长字幕按固定片段切分翻译后重新按索引合并，避免一次请求超出上下文限制。

解析历史迁移新增 `translated_segments_json`、`translation_language` 与 `creator_pack_json`。所有历史 API 继续返回原有字段；不存在新字段时按空值处理。

## 可靠性、安全与合规

- 仅接受 `http`/`https` 的公开视频 URL；批量接口重用并强化单条 URL 的校验。
- 后端绝不把券码明文、DeepSeek 密钥或其他用户的任务信息返回给客户端。
- 券码生成/作废只通过本地卖家脚本执行；该脚本不进入前端打包产物。
- 批量任务、翻译和创作包均使用登录用户身份；前端显示的是当前用户的真实剩余额度而不是固定文案。
- 生成的 AI 文本在前端渲染前必须净化，不能沿用未净化的 `dangerouslySetInnerHTML` 路径。
- 失败退款要可审计：任务项的扣费与退款标记均需持久化，避免用户因重试拿到重复额度或因系统中断被误扣。

## 验收标准

1. 未登录用户访问 `/redeem` 能看到流程说明，兑换时被引导登录；登录后可成功兑换 Pro 周卡并看见准确到期日和额度。
2. 卖家可本地生成、查询、作废一次性 Pro 周卡/月卡/年卡；已使用或作废券码不能再次兑换。
3. 免费用户不能创建批量任务；Pro 每批最多 5 条，Ultra 每批最多 15 条，超限在前后端均被拒绝。
4. 批量任务在刷新页面后仍能显示进度；完成条目出现在个人解析历史并可继续解析；失败条目显示具体原因且只退一次额度。
5. Pro/Ultra 可从带时间轴的字幕生成中英双语 SRT/VTT；时间码不改变，重复打开缓存不重复扣费。
6. Pro/Ultra 可生成并导出 Markdown 创作包；重复打开同一记录读取缓存；没有字幕时不能调用创作包接口。
7. 现有单条下载、字幕、总结、思维导图、历史与兑换流程仍可用。
8. 新增服务单元测试、券码/会员测试和 FastAPI 集成测试覆盖成功、越权、超额、失败退款与缓存命中；前端生产构建通过。

## 发布顺序

1. 先完成额度、券码周卡与兑换中心，确保能稳定交付闲鱼卡密。
2. 再上线批量队列和任务可见性，先限制为低并发。
3. 最后上线翻译与创作包，监测模型成本、失败率与单用户消耗后再调整套餐数值。

不在未验证成本前推广 Ultra 终身无限 AI；已有 Ultra 用户权益保持不受影响。
